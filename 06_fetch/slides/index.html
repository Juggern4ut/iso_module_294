06 – Fetch

Daten laden und senden mit fetch

  • Verstehen, was fetch ist und wie es funktioniert

Grundlagen

Was ist fetch?

fetch ist eine moderne API für HTTP-Anfragen.

Asynchron

arbeitet asynchron

Promise

liefert immer ein Promise zurück

Modern

ersetzt ältere APIs wie XMLHttpRequest

Grundlagen

Grundaufbau von fetch


fetch(url, options)

url

url: Ziel der Anfrage

options

options: Konfiguration (optional)

GET

Einfacher GET-Request


fetch("https://jsonplaceholder.typicode.com/posts")
    .then(response => response.json())
    .then(data => console.log(data));

Ohne Options-Objekt wird automatisch ein GET-Request gesendet.

GET

GET mit async / await


async function loadPosts() {
    const response = await fetch(
        "https://jsonplaceholder.typicode.com/posts"
    );
    const data = await response.json();
    console.log(data);
}
Response

Was ist eine Response?

  • Antwort des Servers
  • enthält Statuscode (z. B. 200, 404)

Daten müssen explizit gelesen werden

Response

Status prüfen


if (!response.ok) {
    throw new Error("Fehler: " + response.status);
}

ok ist true bei Statuscodes 200–299.

Fehlerbehandlung

Fetch mit Fehlerbehandlung


async function loadData() {
    try {
        const response = await fetch(url);
        if (!response.ok) {
            throw new Error("HTTP-Fehler");
        }
        const data = await response.json();
        console.log(data);
    } catch (error) {
        console.error(error);
    }
}
Quiz

Was gibt dieser Code aus?


async function loadData(response) {
    try {
        if (!response.ok) {
            throw new Error("Fehler: " + response.status);
        }
        console.log("Daten geladen");
    } catch (error) {
        console.log("Abgefangen: " + error.message);
    }
}

loadData({ ok: false, status: 404 });

Abgefangen: Fehler: 404 – weil ok false ist, wird der Fehler geworfen und im catch behandelt. "Daten geladen" wird nie ausgegeben.

Grundlagen

HTTP-Methoden

Methode Zweck
GET Daten laden
POST Daten senden
PUT / PATCH Daten ändern
DELETE Daten löschen
POST

POST-Request – Grundidee

POST wird verwendet, um neue Daten an einen Server zu senden.

Dazu werden Options benötigt.

POST

POST mit fetch


fetch(url, {
    method: "POST"
});
POST

Header mitsenden


fetch(url, {
    method: "POST",
    headers: {
        "Content-Type": "application/json"
    }
});

Header beschreiben, wie der Request interpretiert werden soll.

POST

Request-Body senden


fetch(url, {
    method: "POST",
    headers: {
        "Content-Type": "application/json"
    },
    body: JSON.stringify({
        title: "Neuer Eintrag",
        completed: false
    })
});
Quiz

Was wird als Body gesendet?


const body = JSON.stringify({
    title: "Neuer Eintrag",
    completed: false
});

console.log(body);
console.log(typeof body);

{"title":"Neuer Eintrag","completed":false} und string – der Body ist ein JSON-String, kein Objekt.

POST mit async / await


async function createTodo() {
    const response = await fetch(url, {
        method: "POST",
        headers: {
            "Content-Type": "application/json"
        },
        body: JSON.stringify({
            title: "Mein Todo",
            completed: false
        })
    });

    const data = await response.json();
    console.log(data);
}
Header

Typische Header

  • Content-Type
  • Authorization
  • Accept
Header

Warum Header wichtig sind

Format

Server weiss, wie Daten gelesen werden müssen

Authentifizierung

Authentifizierung erfolgt oft über Header

Falsche Header führen zu Fehlern

Zusammenfassung

Zusammenfassung: Fetch-Optionen


fetch(url, {
    method: "POST",
    headers: { ... },
    body: JSON.stringify(data)
});

TL;DR

  • fetch sendet HTTP-Anfragen
  • GET lädt Daten, POST sendet Daten
  • Header beschreiben den Request
  • Body enthält die gesendeten Daten
  • Fehler müssen explizit behandelt werden
